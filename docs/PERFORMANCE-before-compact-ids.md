# 性能记录（2026-11-01）

Windows 11 26200，Intel Core Ultra 9 275HX，24 核 / 24 线程。
Clang 18.1.8，C++23 Release / O3 / ThinLTO；本地原版使用相同编译器和优化参数，C++17。
两者都嵌入相同的 UTF-8 / long-path 应用清单。原版提交：
`4e4df1e567eb3c1475a51af261cba2bfff60b4be`，`ninja/` 工作树没有修改。

当前 CMake 二进制 SHA256：

- sninja：`ca620470fd754a5dfbc86789ca17dda485bbb51f0e528b49130cb75478ad507c`
- 原版：`9f9da4a5612a6a0caf999948e766fb46637923971ca61c3925fe4eef88147e96`

以下五份当前基准的 SHA256 已与磁盘程序逐一核对：`benchmark-current.json`、
`deps-final.json`、`jobs-current.json`、`jobs-chain-current.json`、`compilation-final.json`。
均在 `build-release/` 下保存全部样本。测试与编译未同时运行于基准期间；真实编译用例自身的编译除外。
使用原生对照程序，未使用 Chocolatey 的 .NET 启动器。所有比值为原版耗时 / sninja 耗时，
大于 1 表示 sninja 更快。样本数有限，细小差异不能当作确定收益。

## 清单、图与文件空构建

`scripts/benchmark.py`，每个用例预热 2 次，随机交错测量 21 次，取中位数。

| 用例 | sninja | 原版 Ninja | 比值 |
| --- | ---: | ---: | ---: |
| 启动（--version） | 8.617 ms | 8.287 ms | 0.962× |
| 普通路径解析，10 万边 | 92.968 ms | 160.858 ms | 1.730× |
| 变量路径解析，10 万边 | 119.422 ms | 156.985 ms | 1.315× |
| 图空构建，10 万节点 | 61.752 ms | 102.555 ms | 1.661× |
| 真实文件空构建，2 万文件 | 32.617 ms | 42.807 ms | 1.312× |

当前启动慢约 0.33ms，不能宣称全面超过原版。启动归因实验还观察到路径相关的变化：
同一字节的程序交叉互换两个路径后，四轮各 101 个测量样本的中位差为 0.04–0.14ms；
另一次原路径差约 1ms。原始记录见 `startup-copies.json`、`startup-crossover.json`、
`noop-pipeline.json`。这些实验不能证明差距全来自线程库或全来自环境。

## 大型依赖日志与峰值内存

`scripts/benchmark_deps.py --repeats 15 --recompact`，每个用例预热 2 次，随机交错测量 15 次。
2 万输出，共有 1024 个头文件，每个输出分别有 8、64、256 个头文件依赖。
日志按 Ninja v4 格式生成，命令哈希与平台时间戳取自原版实际构建。两种引擎都必须空构建，
且不能修改依赖日志。另行改动一个头文件，比较精确失效边数与完整干跑计划；
三个用例分别检查 157、1251、5000 条失效边。暖缓存结果不代表所有真实依赖分布。

峰值内存来自 Windows GetProcessMemoryInfo 的 PeakWorkingSetSize，单位为 MiB。

| 依赖/输出 | sninja 空构建 | 原版空构建 | 比值 | sninja 峰值 | 原版峰值 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 41.950 ms | 56.764 ms | 1.353× | 22.4 | 25.2 |
| 64 | 61.210 ms | 81.858 ms | 1.337× | 51.9 | 55.0 |
| 256 | 125.025 ms | 161.197 ms | 1.289× | 142.3 | 144.3 |

`-t recompact` 另行重写构建和依赖日志。每次写完都由所有对照变体交叉空构建，
全部重写完成后再次比较头文件失效计划。写入记录继续逐条 fflush，保留恢复边界。

| 依赖/输出 | sninja 重写 | 原版重写 | 比值 | 同一引擎合并写入前 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 171.618 ms | 190.116 ms | 1.108× | 175.103 ms |
| 64 | 186.694 ms | 233.261 ms | 1.249× | 220.179 ms |
| 256 | 230.631 ms | 365.697 ms | 1.586× | 344.051 ms |

分阶段消融记录保留了各自的二进制 SHA256：

- `deps-buffered.json`：相同大依赖用例，分块读取/单遍转换前 148.350ms，之后 124.457ms。
  单次 `-d stats` 中依赖加载计时由约 44ms 降到约 18ms；这是辅助归因，不是整轮基准。
- `deps-growth.json`：大邻接表改用较小增长比例；高依赖用例峰值由 150.5MiB 降到 142.2MiB。
  此轮耗时为 127.924ms / 125.453ms，小差异不单独认定为确定速度收益。
- `deps-final.json`：合并写记录的同期对照，256 依赖用例重写由 344.051ms 降到 230.631ms。
  原始数据同时保留未合并写入变体的空构建结果。

## 原生短任务和串行依赖链

`scripts/benchmark_jobs.py`，128 个独立原生子进程，计算量为 0 或 5ms。
每个用例预热 1 轮，随机交错测量 7 次，保存父进程 CPU、子进程时间线、启动间隔、
峰值计算并发和构建日志时间。每份输出检查索引、记录长度和标识。
`sync` 使用同一个 sninja 二进制并设置 `SNINJA_ASYNC_LAUNCH=0`，作为启动流水线消融。

| 工作量 | 并行度 | sninja | 原版 Ninja | sync | 原版/sninja |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 μs | 1 | 1038.18 ms | 1069.95 ms | 992.51 ms | 1.031× |
| 0 μs | 2 | 516.39 ms | 536.19 ms | 507.16 ms | 1.038× |
| 0 μs | 4 | 394.53 ms | 436.23 ms | 476.95 ms | 1.106× |
| 0 μs | 24 | 445.09 ms | 503.85 ms | 483.34 ms | 1.132× |
| 5000 μs | 1 | 1715.80 ms | 1692.77 ms | 1740.76 ms | 0.987× |
| 5000 μs | 2 | 862.96 ms | 845.57 ms | 835.39 ms | 0.980× |
| 5000 μs | 4 | 458.32 ms | 476.02 ms | 513.01 ms | 1.039× |
| 5000 μs | 24 | 452.47 ms | 487.31 ms | 476.23 ms | 1.077× |

串行链另测 64 个 5ms 原生任务，指定 -j24：sninja 868.14ms，
原版 873.82ms，sync 864.99ms。只允许一条依赖通路，
时间戳检查每个任务都在前驱结束后运行，结果视为基本持平。

高并发短任务有收益，低并发部分样本仍回退。同一二进制的同步对照在 -j1 也有波动，
不能将全部小差异归因于异步调度。自动策略保留空队列、单链和稀疏任务的直接启动。
一次额外 -d stats 采样见 `process-stats-current.log`：128 次进程启动合计约 377ms。
这反映当前单启动者设计的成本，不能当作跨设计的理论下限。

## 真实 C++ 编译

`scripts/benchmark_builds.py --repeats 7 --jobs 4 24 --variant sync=0`。
120 个真实 C++ 翻译单元，CMake/MSVC Release；每个样本都运行生成程序并检查计算结果，
检查需要编译的边数或确实没有工作。每项随机交错测量 7 次，以下为中位数。

| 用例 | sninja | 原版 Ninja | sync | 原版/sninja |
| --- | ---: | ---: | ---: | ---: |
| clean_j4 | 6953.415 ms | 7038.815 ms | 7012.033 ms | 1.012× |
| clean_j24 | 2797.948 ms | 3065.299 ms | 2957.866 ms | 1.096× |
| incremental_header | 2791.356 ms | 3084.491 ms | 2991.244 ms | 1.105× |
| noop_compiled | 16.508 ms | 16.460 ms | 15.848 ms | 0.997× |

-j24 全量和共享头文件增量的吞吐比约为 1.10×；-j4 和空构建视为基本持平。
历史记录 `compilation.json`、`compilation-current.json`、`compilation-pipeline.json`、
`compilation-sparse.json` 使用各自记录的阶段二进制，不能混作同一版本或挑选最大值。
其中曾出现低并发慢约 1%、空构建慢约 2ms，报告没有删除这些样本。

## 正确性与自举

- Release CTest：461 个单测，同步/异步各 13 组差分集成测试，全部通过。
- MSVC 19.44 AddressSanitizer：461 个测试通过。Clang 18 ASan 本机运行库初始化失败，未计作通过。
- 新增取消活动 I/O/排队任务、完成端口复用、父进程可继承句柄、大量输出和启动失败检查。
- 新增依赖读取边界、大记录、无效长度/ID、非对齐记录、末尾残缺与精确序列化检查。
- 原版与 sninja 相互嵌套使用 Windows jobserver，峰值限制及不共享池的负对照均通过。
- Clang 和 MSVC 均从直接编译种子开始自举，第一/第二阶段 SHA256 相同，第二阶段空构建。
  最新 SHA256 和日志位置见 `docs/STATUS.md`。

## 尚未达成

全面超过 Ninja、所有行为兼容和接近理论极限仍未证明，目标保持进行中。
启动和低并发回退仍需定位；依赖日志、图输入和反向邻接仍存在重复存储。
超长链、超大历史日志、不同依赖分布、冷缓存、尾延迟及其他平台仍需扩展验证。
当前实际验证平台为 Windows x64。
