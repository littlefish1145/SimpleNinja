# 性能记录（2026-11-01，紧凑依赖 ID 阶段）

Windows 11 26200，Intel Core Ultra 9 275HX，24 核 / 24 线程。
Clang 18.1.8，Release / O3 / ThinLTO。sninja 使用 C++23，对照使用 C++17。
当前双方都使用动态 CRT 和相同的 UTF-8 / long-path 应用清单。原版源码保持不变，提交为
`4e4df1e567eb3c1475a51af261cba2bfff60b4be`。所有比值均为原版耗时 / sninja 耗时。

- 当前 sninja SHA256：`6ae03a156b032ae8171817b9e1cd2aa5536dd9a5aeb63c306dfa4ce499ec30c0`
- 当前原版 SHA256：`5194b549570fd4cca42b5402fb508b9521ea5f83feba405e2b465aaabbf4ac80`

当前四份主要基准：`benchmark-compact-final.json`、`deps-compact-final.json`、
`jobs-compact-final.json`、`compilation-compact-final.json`，均在 `build-release/` 下保存全部样本。
二进制 SHA256 已与磁盘逐一核对，所有子进程退出码和实际输出均检查。
对照是本地原生程序，不使用系统 shim。计时期间没有同时构建或跑测试；真实编译用例自身的编译除外。
每项交错随机执行、取中位数。本轮绝对耗时整体高于此前阶段，只比较同期对照。
旧报告保留在 `docs/PERFORMANCE-before-compact-ids.md`，不能混用历史最大收益。

`scripts/benchmark.py`，每个用例预热 2 次、测量 21 次。

| 用例 | sninja | 原版 | 比值 |

| 启动（--version） | 11.911 ms | 11.644 ms | 0.978× |
| 普通路径解析，10 万边 | 96.193 ms | 168.809 ms | 1.755× |
| 变量路径解析，10 万边 | 128.099 ms | 170.813 ms | 1.333× |

生产路径的启动仍慢约 0.27ms。另用 `scripts/benchmark_startup.py --crossover`

合并中位数为 sninja 13.327ms、原版 13.159ms。
路径控制后仍有差距，各轮有波动；启动归因没有解决。该脚本与 benchmark.py 的捕获/超时方式不同，
绝对耗时不应跨脚本相减。

## 大型依赖日志

2 万输出、1024 个共享头文件；每个输出分别有 8、64、256 个依赖。预热 2 次、随机交错测量 15 次。
日志按 Ninja v4 格式生成，命令哈希与平台时间戳来自原版实际构建。
空构建必须没有工作、不能改动 deps 日志；改动一个头文件后比较精确失效边数与完整干跑计划。
三个用例分别验证 157、1251、5000 条失效边。
峰值为 GetProcessMemoryInfo 的 PeakWorkingSetSize，单位为 MiB。

| 依赖/输出 | sninja 空构建 | 原版空构建 | 比值 | sninja 峰值 | 原版峰值 | 改造前峰值 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 48.214 ms | 61.816 ms | 1.282× | 21.8 | 25.2 | 22.5 |
| 64 | 66.736 ms | 91.195 ms | 1.366× | 47.6 | 54.9 | 51.9 |
| 256 | 123.520 ms | 165.855 ms | 1.343× | 123.6 | 144.2 | 142.1 |

改造前是同轮运行的 `sninja-pre-compact.exe`，SHA256 为
`ca620470fd754a5dfbc86789ca17dda485bbb51f0e528b49130cb75478ad507c`。当前日志只保存 32 位 ID，加载到图时才解析为节点；
记录头和 ID 数组一次分配。节点表扩容不使视图失效，日志重写后重新绑定视图。
记录替换、日志重写和日志销毁会释放相应存储。每个依赖的日志存储从 8 字节指针变为 4 字节 ID，
但图输入和反向邻接仍持有指针，因此没有达到整张图的最低存储量。

重写用例执行 `-t recompact`，每次写完都由所有变体交叉空构建，最后再次比较失效计划。
格式和逐记录刷新边界保持一致。

| 依赖/输出 | 当前重写 | 原版重写 | 比值 | 改造前重写 | 改造前空构建 |

## CRT 链接试验

`startup-runtime-crossover.json` 在原型阶段比较动态/静态 CRT 的双方程序，轮换相同路径，
四轮各 101 个测量样本。静态 sninja 合并中位数约 11.637ms，动态约 12.417ms，
当轮静态 sninja 与静态原版基本持平。但 `deps-compact-static.json` 的同期日志重写试验中，
静态 sninja 的 256 依赖用例为 331.616ms，动态变体为 244.372ms，存在显著回退。
这些试验对应各自 JSON 中的原型 SHA256；当前默认恢复动态 CRT。
保留 `configure.py --runtime static` 及 CMake 的 `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded`
作为可选配置。不能通过只比较静态 sninja 与动态原版来宣称算法收益。
